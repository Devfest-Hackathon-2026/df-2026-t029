## 1. 概要

| 項目 | 内容 |
|---|---|
| 機能名 | グッズ交換マッチング（交換ポータル） |
| 優先度 | P2 |
| 担当 | B |
| 目的 | グッズの交換・売買を募集している人同士が、互いを見つけられるようにする |

### 前提（プロジェクト仕様書 4.5 より）

- メルカリのような取引の場ではない。金銭や物のやり取りは、アプリ外で当人同士が行う。アプリは決済・配送を扱わない。
- ユーザーは「譲」と「求」を登録する。交換だけでなく、売買の募集も登録できる。
- 互いの譲と求が一致するユーザーを、自動で提示する。

### 利用の流れ

1. 譲を出す人が投稿する（1つの投稿に譲と求の両方を書ける。譲だけでもよい）。
2. 求の人は掲示板やマッチで探す。自分も投稿すれば、相互マッチ・片方マッチが自動で出る。
3. 気になる投稿に返信する。投稿者が返信を承認すると、返信した人との個人チャットが開く。
4. チャットで詳細を詰め、受け渡しはアプリ外で行う。

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| グッズ | 推しのグッズの商品単位（例：「〇〇 TOUR 2026 ランダムアクスタ」）。共通データとして登録する。チケットは含めない |
| 種類 | グッズの中の区別（例：メンバーA／メンバーB、絵柄1／絵柄2）。任意でメンバー（`oshis` の ID）を紐づけられる |
| 品目 | 「グッズ＋種類」の組。譲・求の最小単位 |
| 投稿 | ユーザーが出す、譲・求の募集1件。取引のタグを付ける |
| タグ | 投稿の取引の希望。交換希望・譲渡（売ります）・買取希望の3つから、複数選べる |
| 譲セット | 投稿の中の譲のまとまり。複数の品目と写真を含み、「この中から N 個」のように選べる数を持つ |
| 求セット | 投稿の中の求のまとまり。品目の指定に加え、幅のある指定（グッズの全種類、メンバー指定）ができる |
| 掲示板 | 推しごとの投稿の一覧 |
| 返信 | 投稿に付ける、誰でも見られるコメント。取引の申し込みにも使う |
| 承認 | 投稿者が返信を受け入れること。承認すると、返信した人との個人チャットが開く |
| 相互マッチ | 相手の譲に自分の求があり、かつ自分の譲に相手の求がある状態 |
| 片方マッチ | 相手の譲に自分の求があるが、相手は自分の譲を求めていない状態 |

## 3. 決定事項

### 3.1 グッズの扱い

- グッズは共通データとして登録し、ユーザーは登録済みのグッズから選んで譲・求を出す。表記ゆれによるマッチングの漏れを防ぐためである。
- 誰かが一度登録したグッズは、他のユーザーも使える（ライブ情報と同じ考え方）。
- グッズの登録に運営の承認は挟まない。ライブと同じく、ログイン済みのユーザーなら誰でも登録・更新でき、変更履歴を残す。ツアーグッズは発売直後から交換が始まるためである。
- グッズの種類には、任意でメンバー（`oshis` の ID）を紐づけられる。
- チケットの譲渡は対象外とする。グッズの種別にチケットを含めない。

### 3.2 譲・求の出し方

- 譲は「セット」単位で出す。1つのセットに複数の品目と写真を含められ、「この中から1つ」のように選べる数を指定できる。
- 求もセット単位で出す。求の出し方は次の3種類とする。

| 求の出し方 | 例 |
|---|---|
| 品目を指定 | アクスタ（メンバーC） |
| グッズの全種類 | ランダムアクスタならどれでも |
| メンバー指定 | メンバーC のグッズなら何でも |

- 品目を選ばず、文章と写真だけの投稿も出せる。この投稿は掲示板には載るが、自動のマッチングの対象外とする。
- 投稿には、取引のタグ（交換希望・譲渡・買取希望）を1つ以上付ける。タグは複数選べる（例：交換優先・買取も可）。
- 譲渡・買取希望の価格は、金額を入力させず「定価」「定価以下」から選ぶ。定価を超える価格は選べない。送料などは備考に書く。
- 投稿には、受け渡し方法（郵送・手渡し。両方可）、手渡しの場合の公演（複数可）、連絡先（X アカウント）、備考を持たせる。
- 投稿は作成者が「募集終了」にできる。
- 写真は1投稿あたり最大8枚、1枚 5MB 以下とする。アップロード前に、長辺 1600px 程度に縮小する。

### 3.3 掲示板

- 投稿を推しごとの一覧（掲示板）で見られるようにする。
- グッズ、譲／求、タグ、手渡しの公演などで絞り込める。
- 一覧は更新日時の新しい順に表示する。投稿の有効期限は設けない。

### 3.4 マッチング

- マッチングは、相互マッチ → 片方マッチの順に表示する。
- 譲セットの「選べる数」はマッチングの判定には使わず、表示のみに使う（「この中から1つ」のどれか1品目でも一致すればマッチとする）。
- タグはマッチングの判定に使わず、結果に表示する。
- 検索のため、投稿には検索用のキーの配列（`giveKeys`・`wantKeys`）を持たせる。譲の品目1つから、次の3種類のキーを作る。

| キー | 形式 | 一致する求の出し方 |
|---|---|---|
| 品目のキー | `item:{goodsId}#{variantId}` | 品目を指定 |
| グッズのキー | `goods:{goodsId}` | グッズの全種類 |
| メンバーのキー | `member:{oshiId}` | メンバー指定（種類にメンバーが紐づいている場合のみ作る） |

- 求は、出し方に応じて上記のいずれか1つのキーを作る。
- 検索の流れ：自分の `wantKeys` で、`giveKeys` に一致するものを含む投稿を探す（Firestore の `array-contains-any`。1回の検索で使える値は30個までのため、超える場合は分けて検索する）。見つかった投稿のうち、相手の `wantKeys` が自分の `giveKeys` と一致するものを相互マッチとする。

### 3.5 連絡・返信・チャット

- 投稿の詳細画面に、X アカウントへのリンクを表示する。
- 投稿への返信を設ける。返信は投稿の詳細画面に時系列で一列に表示し（スレッドにはしない）、募集中の投稿には、ログイン済みのユーザーなら誰でも書ける。
- 返信には、自分の投稿を添付できる。投稿者は、相手の譲を確認してから判断できる。マッチの一覧からは、相手の投稿に自分の投稿を添付して返信する形でつながる。
- 投稿者が返信を承認すると、返信した人との個人チャットが開く。
- チャットは Firestore のみで作り、メッセージをリアルタイムで購読する。メッセージは文字のみで、編集・削除はできない。
- チャット画面の先頭に、きっかけの投稿と返信を表示する。参加者のどちらでも「取引終了」にできる。

### 3.6 スクショからの投稿作成

- X でよく見る「譲求の画像」などのスクリーンショットから、Gemini で譲・求の内容を読み取り、投稿の作成画面に反映する（G-6）。
- 読み取りの仕組みは、ライブ情報のスクショ読み取り（Firebase AI Logic、`GeminiService`）を流用する。読み取った結果は、ユーザーが確認・修正してから投稿する。

### 3.7 写真と料金プラン

- 写真は開発の終盤に追加する（G-7）。それまでは、投稿・譲セットの `images` を空の配列とする。
- 投稿の写真は Cloud Storage for Firebase に保存する。
- Cloud Storage の利用には Blaze プランが必要なため、G-7 の着手時に Blaze に切り替え、Google Cloud 無料トライアル（300ドルのクレジット）の請求先アカウントを紐づける。

### 3.8 不適切な投稿への対策

- ハッカソン版では、運営が Firebase コンソールで投稿を「非表示」にする対応のみとする。
- 通報・ブロックは将来対応とする。

### 3.9 表示名

- 投稿・返信・チャットの表示名は、G-8 でプロフィールを作るまで「匿名」とする。
- 表示名を決める処理は1か所にまとめ、G-8 ではそこだけを差し替える。

## 4. 画面構成

| 画面 | 内容 |
|---|---|
| 交換トップ | 「掲示板」「マッチ」「自分の投稿」の3つを切り替えて表示する |
| 投稿の作成・編集 | 対象の推し、タグ、譲セット・求セット、写真、条件、連絡先を入力する。スクショからの読み取りもここから行う |
| 投稿の詳細 | 投稿の内容、写真、X へのリンク、返信の一覧と入力（自分の投稿の添付）、返信の承認 |
| グッズの登録・検索 | 共通データのグッズを検索し、なければ登録する |
| チャット | チャットの一覧と、承認した返信をきっかけにした1対1のやり取り |

## 5. データ構造

詳細な項目は `database.md`（3.9〜3.13、4章、5章、6章）に記載する。

```
goods/{goodsId}              グッズ（共通データ。誰でも登録・更新できる）
  └ history/{historyId}      変更履歴
tradePosts/{postId}          投稿（タグ・譲セット・求セット・検索用キー・条件）
  └ replies/{replyId}        返信（投稿者が承認するとチャットが開く）
chats/{chatId}               個人チャット（ID は {postId}_{返信した人の uid}）
  └ messages/{messageId}     メッセージ
```

## 7. 非機能要件

- 投稿は、ログイン済みのユーザーだけが読める。作成・編集・募集終了は作成者だけができる。
- 非表示にした投稿は、掲示板とマッチングに表示しない。非表示への変更は運営だけができる。
- 返信は、ログイン済みのユーザーだけが読める・書ける。削除は書いた本人だけ（承認前に限る）、承認は投稿者だけができる。
- チャットは、参加者の2人だけが読み書きできる。チャットの作成は、返信の承認時に投稿者が行う。
- 写真は、ログイン済みのユーザーだけが読める。アップロード・削除は投稿者だけができる。Storage のルールで、画像形式と 5MB 以下に制限する。
