## 1. 概要
 
| 項目 | 内容 |
|---|---|
| 機能名 | グッズ交換マッチング（交換ポータル） |
| 優先度 | P2 |
| 担当 | B |
| 目的 | グッズの交換・売買を募集している人同士が、互いを見つけられるようにする |
 
### 前提（プロジェクト仕様書 4.5 より）
 
- メルカリのような取引の場ではない。金銭や物のやり取りは、アプリ外で当人同士が行う。アプリは決済・配送を扱わない。
- ユーザーは「譲」と「求」を登録する。交換だけでなく、売買の募集も登録できる。
- 互いの譲と求が一致するユーザーを、自動で提示する。
 
## 2. 用語定義
 
| 用語 | 定義 |
|---|---|
| グッズ | 推しのグッズの商品単位（例：「〇〇 TOUR 2026 ランダムアクスタ」）。共通データとして登録する |
| 種類 | グッズの中の区別（例：メンバーA／メンバーB、絵柄1／絵柄2）。任意でメンバー（`oshis` の ID）を紐づけられる |
| 品目 | 「グッズ＋種類」の組。譲・求の最小単位 |
| 投稿 | ユーザーが出す、譲・求の募集1件 |
| 譲セット | 投稿の中の譲のまとまり。複数の品目と写真を含み、「この中から N 個」のように選べる数を持つ |
| 求セット | 投稿の中の求のまとまり。品目の指定に加え、幅のある指定（グッズの全種類、メンバー指定）ができる |
| 掲示板 | 推しごとの投稿の一覧 |
| 相互マッチ | 相手の譲に自分の求があり、かつ自分の譲に相手の求がある状態 |
| 片方マッチ | 相手の譲に自分の求があるが、相手は自分の譲を求めていない状態 |
 
## 3. 決定事項
 
### 3.1 グッズの扱い
 
- グッズは共通データとして登録し、ユーザーは登録済みのグッズから選んで譲・求を出す。表記ゆれによるマッチングの漏れを防ぐためである。
- 誰かが一度登録したグッズは、他のユーザーも使える（ライブ情報と同じ考え方）。
- グッズの種類には、任意でメンバー（`oshis` の ID）を紐づけられる。
 
### 3.2 譲・求の出し方
 
- 譲は「セット」単位で出す。1つのセットに複数の品目と写真を含められ、「この中から1つ」のように選べる数を指定できる。
- 求もセット単位で出す。求の出し方は次の3種類とする。
 
| 求の出し方 | 例 |
|---|---|
| 品目を指定 | アクスタ（メンバーC） |
| グッズの全種類 | ランダムアクスタならどれでも |
| メンバー指定 | メンバーC のグッズなら何でも |
 
- 品目を選ばず、文章と写真だけの投稿も出せる。この投稿は掲示板には載るが、自動のマッチングの対象外とする。
- 投稿には、交換／売買／どちらでも、受け渡し方法（郵送／手渡し）、手渡しの場合の公演、連絡先（X アカウント）、備考を持たせる。
- 投稿は作成者が「募集終了」にできる。
 
### 3.3 掲示板
 
- 投稿を推しごとの一覧（掲示板）で見られるようにする。
- グッズ、譲／求、交換／売買、手渡しの公演などで絞り込める。
 
### 3.4 マッチング
 
- マッチングは、相互マッチ → 片方マッチの順に表示する。
- 譲セットの「選べる数」はマッチングの判定には使わず、表示のみに使う（「この中から1つ」のどれか1品目でも一致すればマッチとする）。
- 検索のため、投稿には検索用のキーの配列（`giveKeys`・`wantKeys`）を持たせる。譲の品目1つから、次の3種類のキーを作る。
 
| キー | 形式 | 一致する求の出し方 |
|---|---|---|
| 品目のキー | `item:{goodsId}#{種類}` | 品目を指定 |
| グッズのキー | `goods:{goodsId}` | グッズの全種類 |
| メンバーのキー | `member:{oshiId}` | メンバー指定（種類にメンバーが紐づいている場合のみ作る） |
 
- 求は、出し方に応じて上記のいずれか1つのキーを作る。
- 検索の流れ：自分の `wantKeys` で、`giveKeys` に一致するものを含む投稿を探す（Firestore の `array-contains-any`。1回の検索で使える値は30個までのため、超える場合は分けて検索する）。見つかった投稿のうち、相手の `wantKeys` が自分の `giveKeys` と一致するものを相互マッチとする。
 
### 3.5 連絡
 
- 投稿の詳細画面に、X アカウントへのリンクを表示する。
- アプリ内チャットを提供する（G-5）。
 
### 3.6 スクショからの投稿作成
 
- X でよく見る「譲求の画像」などのスクリーンショットから、Gemini で譲・求の内容を読み取り、投稿の作成画面に反映する（G-6）。
- 読み取りの仕組みは、ライブ情報のスクショ読み取り（Firebase AI Logic、`GeminiService`）を流用する。読み取った結果は、ユーザーが確認・修正してから投稿する。
 
### 3.7 写真と料金プラン
 
- 投稿の写真は Cloud Storage for Firebase に保存する。
- Cloud Storage の利用には Blaze プランが必要なため、G-0 で Blaze に切り替え、Google Cloud 無料トライアル（300ドルのクレジット）の請求先アカウントを紐づける。
 
## 4. 画面構成
 
| 画面 | 内容 |
|---|---|
| 交換トップ | 「掲示板」「マッチ」「自分の投稿」の3つを切り替えて表示する |
| 投稿の作成・編集 | 対象の推し、譲セット・求セット、写真、条件、連絡先を入力する。スクショからの読み取りもここから行う |
| 投稿の詳細 | 投稿の内容、写真、X へのリンク、チャットの開始 |
| グッズの登録・検索 | 共通データのグッズを検索し、なければ登録する |
| チャット | 投稿をきっかけにした、ユーザー同士の1対1のやり取り |
 
## 5. データ構造（概要案）
 
詳細な項目は G-0 で確定し、`database.md` に追記する。
 
```
goods/{goodsId}              グッズ（共通データ）
  name, groupIds, oshiIds, liveId（ツアーグッズの場合）,
  variants（種類の一覧。各要素は 名前＋任意のメンバー ID）,
  createdBy / createdAt / updatedBy / updatedAt
 
tradePosts/{postId}          投稿（ログイン中の全員が読める。作成者だけが編集）
  uid, groupIds, oshiIds（対象の推し）,
  gives（譲セットの一覧。各要素は 品目の一覧・選べる数・写真・備考）,
  wants（求セットの一覧。各要素は 出し方・品目など・備考）,
  giveKeys, wantKeys（検索用のキー。3.4）,
  method（交換／売買／どちらでも）, handover（郵送／手渡し）, performanceId,
  xAccount, note, images, status（募集中／終了）,
  createdAt / updatedAt
 
chats/{chatId}               チャット（参加者の2人だけが読み書きできる）
  └ messages/{messageId}     メッセージ
```
 
## 6. 開発ステップ
 
各ステップは、着手時にさらに小さなステップに分けて進める。
 
| Step | 内容 |
|---|---|
| G-0 | データ構造の確定と `database.md` への追記、セキュリティルール、Blaze への切り替えと Cloud Storage の準備 |
| G-1 | グッズの登録・検索（共通データ。種類にメンバーを紐づけ） |
| G-2 | 投稿の作成（譲・求のセット、選べる数、写真、条件）と、自分の投稿の管理 |
| G-3 | 掲示板（推しごとの投稿一覧と絞り込み） |
| G-4 | マッチング（相互マッチ → 片方マッチ。幅のある求も対象） |
| G-5 | 連絡：投稿の詳細、X へのリンク、アプリ内チャット |
| G-6 | スクショ（譲求の画像）から投稿を作る |
 
## 7. 非機能要件
 
- 投稿は、ログイン済みのユーザーだけが読める。作成・編集・募集終了は作成者だけができる。
- チャットは、参加者の2人だけが読み書きできる。
- 写真は、ログイン済みのユーザーだけが読める。アップロード・削除は投稿者だけができる。
 
## 8. 未決定事項
 
以下は未決定である。LLM は独自に確定させず、提案として提示すること。
 
- `goods`・`tradePosts`・`chats` の詳細なデータ項目（G-0 で確定する）
- グッズの登録に運営の承認を挟むか（推しと同じ承認制か、ライブと同じく誰でも登録できるか）
- アプリ内チャットの実装方式（Firestore のみで作るか、など。プロジェクト仕様書 9章と共通）
- 掲示板の投稿への返信（コメント）機能を設けるか
- 売買の価格の扱い（表示の有無、定価を超える価格を認めるか）
- チケットの譲渡を対象に含めるか（法令上の制限があるため、対象外とする案がある）
- 不適切な投稿への対策（通報・ブロック・非表示など）
- 投稿の有効期限（一定期間で自動的に募集終了にするか）
- 写真の枚数・サイズの上限
