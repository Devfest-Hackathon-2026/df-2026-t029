### 4.2 投稿の画面の骨組み（V1）

`HakoPageScaffold`（タイトル「投稿をまとめて編集」・戻る）の本体を、次の縦並びにする。保存する画像を描くための画面の外の部分（`_captureKey` の `RepaintBoundary`。`Positioned(left: -(captureWidth + 100))`）は**今のまま残す**（`Offstage` や `Opacity 0` にしない）。

1. **固定部分**（背景 `BrandColors.paper`・下に太さ 2 の `ink` の線・余白 上10 左右16 下8）
   - 投稿先のタブ（X／Instagram。今の `_Tabs`。**説明の文は出さない**。高さ 40 以上）
   - プレビュー: `ShareTicketView`（`hints: false`。タップで編集はしない）。**高さ 215 を上限**に、形の比率で幅を決め、中央に置く。画面の高さの 30% も超えない（小さい画面・キーボードが開いたとき。P2。`MediaQuery.sizeOf(context).height * 0.3` と 215 の小さいほう）。
   - 注意文（4.7 の `shareImageNotes`。あるときだけ）を、プレビューの下に小さな説明（情報アイコン＋文）で出す。固定部分の中。
2. **タブの帯**（高さ 48・下に太さ 2 の `ink` の線）: 「中身を直す」「のせる部分」「大きさ」。選んでいるタブは、下に太さ 4 の線（アクセント色）＋太字。`Semantics(selected: …)`・キー `share_ptab_content`・`share_ptab_parts`・`share_ptab_size`。選んでいるタブは画面の `State` に持つ（初期は「中身を直す」。画面を開くたびに戻る）。
3. **パネル**（`Expanded`。タブの中身を `ListView` か `SingleChildScrollView` に入れる。パネルが切り替わると、スクロールは先頭に戻ってよい）
   - 選んでいるタブの中身（4.3・4.5・4.6）
   - **投稿の欄**（キー `share_postend`。上に太さ 3 の `ink` の線・上の余白 28）: 見出し「投稿の文章」＋今の `_captionField`、見出し「投稿する」＋今の `_xActions`／`_igActions`。**中身は今のまま**（キー・文言・動作を変えない）。

**状態の置き場所（重要）**: セトリ・感想の入力の `TextEditingController`、下書き、選んでいるタブは、**画面の `State` に持つ**（タブの中のウィジェットに持たない）。タブを切り替えても入力が消えない・フォーカスが外れないようにする。投稿の文章の `_captionCtl` も画面の `State` のまま。

2. **セトリ**: 複数行の入力欄（最小6行・今の `share_edit_input` と同じ見た目・同じ入力の検査 `validateTicketField`）。ヒント「覚えている曲から、1行に1曲ずつ書けます。」＋改行して「例）」「1. 曲名」「2. 曲名」。キー `share_setlist_input`。

### 4.4 投稿用の写真（V3）

**考え方**: 「SNSに出す写真」は、記録の写真（`memory.images`。最大8枚。表紙が先頭）の中から、**投稿先ごとに**選ぶ。選び方を変えても記録は変わらない。記録の写真が増えたり減ったりしたら、自動で追いかける。

- **未操作の投稿先**: 記録の先頭4枚（`memory.images.take(4)`）。
- **操作したあとの投稿先**: 自分の一覧（最大4枚）。記録から外れた写真（`memory.images` に無い）は一覧から落とす。記録に足された写真は「ほかの候補」に出る。
- 一覧の状態は `ShareState.sharePhotos`（投稿先ごと。`null`＝未操作）（7章）。画面を閉じたら捨てる（保存しない）。

**ブロックの作り**（見本の `photosBlock('share')`）:

1. 説明（情報アイコン＋文。`ainote` の見た目）: 「**{X または Instagram}に投稿する写真だけを選べます。**{操作したあと：記録とは別に選んでいます。／未操作：いまは、記録の写真と同じです。}ここで外したり足したりしても、**記録の写真は変わりません**。画像に入るのは4枚までです。」（太字の部分は `TextSpan` の太字）
2. 操作したあとだけ、リンク「記録と同じ写真に戻す」（キー `share_photo_reset`）。押すと `sharePhotos[target] = null`・トースト「記録と同じ写真に戻しました」。
3. **選んでいる写真**（最大4枚）: 小さな正方形のグリッド（1行4つまで）。各写真に、順番の小さな丸（1〜4。1が一番大きく出る）と、右上の ✕（「{n}枚目の写真を外す」。タップ領域 44px 以上。キー `share_photo_remove_{i}`）。0枚のとき: 「この投稿には、写真を入れていません。下の候補から選べます。」
4. **ほかの候補**（記録の写真のうち、いま選んでいないもの。あるときだけ）: 見出し「ほかの候補（タップで追加）」＋グリッド。各写真は全体がボタン（「{n}枚目の候補を追加」。右下に ＋ の丸。キー `share_photo_add_{i}`）。**すでに4枚のときに押すと、何も足さず、トースト（SnackBar）「画像に入る写真は、4枚までです」**。
5. 記録に写真が0枚のとき: 「記録に写真がありません。「記録の写真を直す」から足せます。」
6. リンク「記録の写真を直す（Googleフォト・端末から追加）」（キー `share_photo_edit_record`）: 既存の `showPhotosSheet(context, memory: memory)` を開く。閉じたあと、記録が変わっていれば自動で追いかける（上のとおり。何もしなくてよい）。
- 写真の表示は `StorageImage(path:)`（記録の画面の `ticket_card.dart` が使っている部品）。
- 追加するときの順は、一覧の末尾。並べ替えはしない。

### 4.5 タブ「のせる部分」（V4）

1. 冒頭の説明: 「{X または Instagram}の画像と文章に、どの部分をのせるかを選びます。」
2. **表**（見本の `.mx`）: 列見出し「部分」「画像に」「文章に」。行: 写真（画像のみ）・日付・会場（画像・文章）・セトリ（画像・文章）・感想（画像・文章）・ハッシュタグ（文章のみ）・「おしあし」マーク（画像のみ）。**のせられない欄は「—」**。各セルはスイッチ（見た目は、記録の画面の公開スイッチなど既存のスイッチの部品があればそれ。無ければ `Switch`）。タップ領域 48px 以上。状態は `ShareConfig`（`toggled`。**押せない組み合わせは表に出さない**）。`Semantics`: 「写真を画像にのせる」のように、部分の名前＋層。キー `share_part_{photo|info|setlist|memo|tags|mark}_{image|caption}`。
   - 手直しした文章は、スイッチを変えても**残る**（4.0）。
3. 見出し「画像の見た目」: 今の `_look()` の中身（画像の形・デザイン・背景）を、折りたたみ（`ExpansionTile`）の**外に**出して並べる。
   - 画像の形: 今の `shareFormats[target]`（キー `share_format_{i}`）。
   - デザイン: **チケット／写真メイン**（キー `share_design_ticket`・`share_design_photo`。**コラージュは無い**）。
   - 背景: **7色**（キー `share_bg_{i}`。今の `_BgSwatch`・`shareBackgrounds`・`shareBackgroundNames`）。選んでいる色にチェック。

### 4.6 タブ「大きさ」（V5）

- 冒頭の説明: 「{X または Instagram}の画像の中の、大きさを変えます。上のチケットを見ながら動かせます。」
- **スライダー3つ**（それぞれ、見出し・いまの値・小〜大の両端の文字・`Slider`）。値の文字は、100 のとき「ふつう」、それ以外は「85%」のように。刻みは 5。動かしている間、プレビューが即時に変わる。
  1. 「写真の大きさ（チケットに占める広さ）」: 50〜150（20分割）。キー `share_size_photo`。**デザインが「写真メイン」のときは、スライダーの代わりに説明「デザインが「写真メイン」のときは、写真は画像いっぱいに入ります。大きさは変えられません。」を出す。**
  2. 「日付・会場の文字の大きさ」: 60〜140（16分割）。キー `share_size_info`。
  3. 「セトリの文字の大きさ」: 60〜140（16分割）。キー `share_size_setlist`。

### 4.7 シェア画像の変更（V6）

**写真（最大4枚）**: `ShareTicketView` は写真を最大4枚（`kShareMaxPhotos`）まで受け取る。並べ方（チケットの写真の欄・縦も横も同じ並べ方）:

| 枚数 | 並べ方 |
|---|---|
| 1 | いっぱいに1枚 |
| 2 | 左右に同じ幅で2枚 |
| 3 | 左に大きく1枚（幅 2：1）、右に縦に2枚（今のまま） |
| 4 | 2×2（同じ大きさ） |

すき間は今と同じ 0.5u。「写真メイン」は今のまま、先頭の1枚だけを使う（4枚渡されても1枚目だけ）。写真が0枚のときの空の枠は今のまま。

**大きさの反映（チケットのデザイン。見本の 365〜380行）**。「今の値」は、`share_ticket_view.dart` に書いてある、いまの大きさ。掛ける値は 7章の `ShareSizes`（`photo`＝pm・`info`＝fi・`setlist`＝fs）:

- **写真（pm）**: 縦長の形は、写真の欄の高さ＝いまの高さ（25／30／54 u。`_verticalRows`）×pm。横長は、写真の欄の幅＝本文の行の幅の 34% × pm（本文はのこり）。pm を大きくすると本文が狭くなるので、下の「自動で絞る」が働く。
- **日付・会場（fi）**: 縦長は、半券の高さ＝いまの高さ（19／20／26 u）×fi。横長は、半券の幅＝25u×fi。日付の文字（縦 6.4u・横 4.6u）と会場の文字（縦 2.7u・横 2.3u）も×fi（いまの値に掛ける）。
- **セトリ（fs）**: セトリの行の文字（縦 3.3u・横 2.6u。いまの値）と「ほか○曲」の文字×fs。
- **写真メイン**（P2）: 日付・会場の行×fi、セトリ・感想の行×fs。写真の大きさ（pm）は効かない。P1 では、写真メインに大きさが効かなくてもよい（スライダーは日付・会場とセトリを出したままにしてよいが、効かない旨の説明は出さない。P2 で効くようにする）。
- 大きさを変えても、**保存する画像（PNG）にも同じに反映される**（プレビューと同じ部品・同じ割合）。

**自動で絞る（チケットのデザインだけ）**:

セトリと感想は、画像の本文に入る分だけを出す。入りきらないときは、**次の順で、入るまで**絞る:

1. 感想の行数を 3 → 2 → 1 に減らす（今の文字数の上限 `maxMemoChars` で切ったあとの文を、最大3行の省略表示にする。最初から3行まで）。
2. セトリの行を**後ろから**1行ずつ消す（最低1行は残す）。消した分は「ほか○曲」（○＝全曲数−見えている曲数）。
3. それでも入らなければ、感想の枠ごと出さない。

- はじめに出すセトリは、チケットのデザインでは**全曲（最大24曲）**。写真メインは今のまま `maxSetlist`（先の固定の上限）。
- セトリが5行以上のとき、2列に分ける（今のまま）。ただし、横長で写真（pm）が 120% を超えるときは1列。
- 「入るか」の判定は、本文の領域の高さ（u で表した、半券・写真・上の帯を引いた残り）と、文字の高さを、`TextPainter` で測って決める（5.7）。**プレビューと保存する PNG で同じ結果になる**（どちらも u を基準に同じ割合で測る。文字は `MediaQuery.withNoTextScaling`＝端末の文字の拡大に影響されない）。
- 結果（見えているセトリの曲数・感想を消したか）は、`ShareTicketView` の `onFit` で画面に知らせる（プレビューだけが渡す。同じ値が続くときは呼ばない。呼び出しは描画のあと `addPostFrameCallback`）。

**注意文**（プレビューの下。7章の `shareImageNotes`。複数あるときは改行でつなぐ）:

| 場合 | 文 |
|---|---|
| チケット・セトリを画像にのせている・自動で絞って全曲は入らなかった | 「セトリは、画像には先頭○曲まで入ります。全曲は文章にのせられます。写真や文字を小さくすると、もっと入ります。」 |
| 写真メイン・セトリを画像にのせている・`maxSetlist` を超えた | 「セトリは、画像には先頭○曲まで入ります。全曲は文章にのせられます。」（今のまま） |
| 感想を画像にのせている・文字数の上限を超えて「…」で切った（感想を消していないとき） | 「感想は、画像には○文字までです。全文は文章にのせられます。」（今のまま） |
| チケット・感想を自動で消した | 「感想は、画像に入りきらないため、画像にはのせていません。写真や文字を小さくすると入ります。」 |

3. **各タスクの最初に、方針を3〜5行でリーダーに送る。返事を待たずに書き始める。**（`dev-data`・`dev-ui`・`dev-qa` の定義には「返事を待つ」とあるが、**この計画書とチームメイト作成時の指示が優先**する。）リーダーは、問題があるときだけ返事をする。タスクを終えたら、完了報告のあと、依存が解けている次のタスクへ**すぐに進む**。
4. **作業ツリーを壊れたまま放置しない。** `ShareConfig`・`ShareState` に足すときは、`copyWith`・`toggled`・`initial()` のどれも直す（**足し忘れると、設定が黙って初期値に戻る**）。
5. **品質ゲート:** タスクを完了にするたびに `.claude/hooks/quality-gate.sh` が動く。失敗すると差し戻される。
6. **見た目は数値で合わせ、見本で確かめる。** 4章の数値と見本の CSS を見比べる。見本を別のタブで並べて確かめるのは人間（12章）。
7. **実装タスクを終えたら、`qa` にレビューを依頼する。**
8. **入力の状態を、タブの中に持たない**（4.2）。タブを切り替えて入力が消える・フォーカスが外れるのは、最もありがちな不具合。
9. **記録の写真を、投稿の画面から変えない。** 4.4 の操作はどれも `ShareState` だけを変える。`memoryEditorProvider.savePhotos` を呼ばない。
10. **古い一覧に注意。** 記録の写真が変わったあと（シートを閉じたあと）、`effectiveSharePhotos` が追いかける。`State` に写真の一覧のコピーを持たない（常に `memory.images` と `ShareState` から計算する）。
11. **`onFit` で無限に再描画しない。** 同じ値のときは呼ばない（`==` で比べる）。呼び出しは描画のあと。
12. **座席を SNS に出さない。** 画像・文章・URL・クリップボードのどこにも座席が入らない。`ShareContent` に座席を持たせない。レビューでも必ず見る。
13. **例外の文字列を画面に出さない。**（`'$e'` を `Text` に入れない。）
14. **ログに個人の情報を出さない。** 写真のバイト列・Storage のパス・メール・座席を `debugPrint`・例外・テストの出力に出さない。
15. **判断を記録する。** 比べた案・選んだ理由・捨てた案は、リーダーが `notes/判断ログ_memory_share_v3.md` に追記する（5章の回答を必ず含める）。

## 14. 使用量の上限で止まったときのために

- リーダーは `notes/memory_share_v3_進捗.md` を、**タスクが1つ終わるたび**に更新する（状態・担当・触ったファイル・次にやること・ユーザーに聞きたいこと）。止まって再開するときは、まずこのファイルを読み、終わったタスクはやり直さない。
- Claude Code が終了してチームメイトがいなくなったら、まだ終わっていないタスクの担当だけを作り直す（13章の指示に「notes/memory_share_v3_進捗.md を読み、自分の未完了のタスクから再開すること」を足す）。
- 使用量を抑えるルール（全員）: メッセージは短く、ファイルの中身やテストの出力を丸ごと貼らない。作業中のテストは関係するファイルだけを実行し、全体は完了時の品質ゲートに任せる。長い出力は末尾だけを見る。計画書は自分に関係する章だけを読み直す。進み具合の確認のためだけのメッセージを送り合わない。
- 許可の確認で止まらないように、シェルのコマンドは1つずつ実行する（`;`・`&&`・`|` でつながない、`$変数` を使わない）。ファイルの読み書き・検索は Read・Edit・Grep などの道具を使う。
