## 3. 決定事項：ライブ一覧（Fd-1・Fd-2）
 
### 3.1 全体の並び
 
上から次の順に並べる（1つの `ListView`）。
 
1. 見出し「今後のライブ」と、自分の今後のライブのタイムライン（3.2）
2. その区画の右下に「ライブを追加」ボタン（`/lives/add`）
3. フォロー中の推しごとの「◯◯の今後のライブ」（3.3）
4. 見出し「終了」と、終了したライブ（今の `_LiveTile` のまま）
- 右下の FAB「ライブを追加する」はやめる（2 のボタンに置き換える）。
- 今の「ライブ一覧はまだ空です」の画面（`_EmptyView`）はやめる。自分のライブが0件でも 3 は出す。0件のときは 1 に「今後のライブはまだありません」を出す。
### 3.2 タイムライン（Fd-1）
 
- 新しい部品 `LiveTimelineItem`（`lib/features/live/live_timeline.dart`）。上と下の区画で使う。
- 左に縦の線（墨 2px）を通し、各ライブの位置に丸印（直径 12、白の地に墨 2px の枠）。いちばん近い今後のライブ（自分の一覧の先頭）だけ丸を墨で塗る。線は最初の丸から最後の丸までつなぐ。
- 右に、ライブ名（15）・出演者（12・`BrandColors.sub`）・「次の公演 …（全n公演）」（12・`sub`。今の `_LiveTile._dateLine` と同じ文）。
- `trailing`（右端に置く部品）を受け取れるようにする（下の区画の「追加済」「追加する！」に使う）。
- 行を押すとライブ詳細（`/lives/{liveId}`）。
### 3.3 推しの今後のライブ（Fd-2）
 
- 新しい部品 `OshiUpcomingLivesSection`（`lib/features/live/oshi_upcoming_lives_section.dart`）。推し1つ分の区画。
- 並べる推し：フォロー中の推し（`followingOshisProvider`）。最推しがいれば先頭、ほかは `followingOshisProvider` の順。
- 見出し：推しの札（`OshiKindBadge`、直径 28）＋「{推しの名前}の今後のライブ」。
- 中身：`liveSearchProvider((targets: FollowTargets.fromFollowing([推し]), query: ''))` のうち、終了していないもの（`!isEnded`）。個人の区画には所属グループのライブも入る（「ライブを追加する」画面と同じ）。同じライブが複数の区画に出てもよい。
- 1つの区画に出すのは最初の5件まで。6件以上なら下に「すべて見る（n件）」を出し、押すとその場で全部出す（覚えない）。
- 今後のライブが0件の推しは、見出しの下に「今後のライブは登録されていません」（12・`sub`）。
- 各行の右端：
  - 自分の一覧に入っている（`myLiveIdsProvider` に含まれる）→「追加済」（チェックのアイコン＋文字、`sub`。押せない）。
  - 入っていない →「追加する！」（`FilledButton`、高さ 36）。押すと `myLiveRepositoryProvider.add(uid, liveId)` → 成功したら `addLiveToCalendar(context, ref, liveId)`（「ライブを追加する」画面と同じ）。処理中は押せない。失敗したら SnackBar「ライブ一覧に追加できませんでした。もう一度お試しください」。
  - 外す操作はここには置かない（ライブ詳細か「ライブを追加する」画面で行う）。
- フォロー中の推しがいないとき：「推しをフォローすると、推しの今後のライブがここに出ます」と「推しを探す」ボタン（`/oshi/search`）。
- 読み込み中・エラーは区画ごとに出す（ほかの区画は出したまま）。エラーは「ライブを読み込めませんでした」と「もう一度読み込む」（`live_add_page.dart` の `_Results` と同じ invalidate）。
## 4. 決定事項：掲示板の投稿カード（Fd-3）
 
`_BoardCard`（`lib/features/trade/trade_board_view.dart`）だけを変える。自分の投稿の一覧（`my_trade_posts_view.dart`）と `TradePostSummaryLines` は変えない。
 
上から次の順に並べる。
 
1. **名前の行**：左にアイコン（`UserAvatar`）と名前（自分の投稿なら「自分」のチップ）、右端に「更新：2026年11月8日」（日付だけ、`bodySmall`）。保存中（`updatedAt` が null）は「保存中…」。
2. **写真**：投稿のすべての写真（投稿全体 → 譲セットの順）を横に並べる。
   - 2枚ぶんの枠を横に並べる（それぞれ幅を半分ずつ、縦横比 4:3、角丸 8、間 8）。
   - 1枚なら左の枠だけ（右はあける）。3枚以上なら2枚目の上に「+n」（半透明の墨の地に白の文字）。
   - 写真が無ければこの行は出さない。
   - すべての写真を返す `allPhotosOf(post)` を `trade_post_summary.dart` に足す（`firstPhotoOf` は残す）。
3. **譲**：「譲：」＋ `giveSummary(post)`（`bodyMedium`）。無ければ出さない。
4. **求**：「求：」＋ `wantSummary(post)`（`bodyMedium`）。無ければ出さない。
5. **そのほか**（12・`BrandColors.sub`、各1行で省略は「…」）：
   - 対象の推し（`targetNames`）
   - タグと受け渡し（例：「交換希望・買取希望／価格：定価以下 ・ 受け渡し：手渡し・郵送」）
   - 品目なしの投稿は「品目なし（自動のマッチングの対象外）」
- 右の 56×56 の写真（`TradePostWithThumb`）は掲示板では使わない。
- 左端の推しの色の帯（Fc 5.3）は残す。
- 日付だけの書式の関数が無ければ、`trade_post_summary.dart` に `formatDateOnly(DateTime)`（日本時間で「YYYY年M月D日」）を足す。
## 5. 決定事項：推しページ（Fd-4・Fd-5）
 
### 5.1 推しの行（Fd-4）
 
`OshiListTile` の並びを、手描きのとおり次のようにする。
 
```
         [アイドル]
 (札)    グループX            ☆ [フォロー] [メンバーをまとめてフォロー] ⋮
  ▼      所属：…・申請中など
```
 
- **ジャンルのチップ**：名前の上に小さく出す（`HakoTagChip(oshi.genre.label)`）。
- **種別のチップ（グループ／個人）はやめる**（札で分かるため）。所属・申請中のチップは名前の下に残す。
- **▼（開閉）**：グループの行で、`membersExpanded` が null でないとき、札の下に ▼／▲ のアイコンボタン（`Icons.arrow_drop_down`／`arrow_drop_up`、`tooltip` は「メンバーを開く」「メンバーを閉じる」）。「メンバー ▼」のチップはやめる。行を押しても今までどおり開閉する。`membersExpanded` が null（シートで開く形）のときは今までどおり「メンバーを見る ›」のチップ。
- **☆（最推し）**：今までどおり（`onToggleFavorite` があるときだけ）。
- **フォローのボタン**：今までどおり。
- **メンバーをまとめてフォロー**：グループの行に新しい引数 `showFollowAll` を足し、true ならフォローのボタンの右に `FollowAllMembersButton` を出す。文言を「メンバーをまとめてフォロー（n人）」に変える（0人なら「全員フォロー中」、承認済みのメンバーがいなければ出さない。動きは Fc 4.2 のまま）。
- **⋮**：新しい引数 `menu`（5.3 のメニュー項目の一覧）。空でなければ右端に `PopupMenuButton`（`Icons.more_vert`、`tooltip` は「その他」）。
- **幅が狭いとき**：行の幅が基準未満なら、☆・ボタン類・⋮ を名前の下の行に右寄せで並べる（`Wrap`）。基準以上なら1行。基準は、まとめてフォローがある行は 760、ほかの行は 420（Fd-6x。まとめてフォローは横に長く、PC の本文の幅 640 でも名前が潰れたため）。
### 5.2 メンバーの一覧（Fd-4）
 
`GroupMembersPanel` を次のようにする。
 
- 新しい引数 `showFollowAllButton`（省略時 true）と `withActions`（省略時 false）。推しページでは `showFollowAllButton: false`（グループの行に移したため）・`withActions: true`。推しを探す画面はグループの行にまとめてフォローを置かないので、上のボタンを残す。シート（`group_members_sheet.dart`）の見出しの下のボタンも残す。
- メンバーの行にも ☆ と ⋮ を出す（手描きのとおり）。
  - ☆：フォロー中のメンバーなら今までどおり最推しにする・外す。フォローしていないメンバーなら、先にフォローしてから（`runFollowAction`）最推しにする（`runFavoriteAction`）。フォローに失敗したら最推しにしない。申請中のメンバーには ☆ を出さない（フォローできないため）。
  - ⋮：5.3 のメニュー。
- 縦線・字下げ・「メンバーを申請する」は今までどおり。
### 5.3 ⋮ のメニュー
 
今ある操作だけを入れる。新しい画面は作らない（推しの詳細画面は `add_D.md`）。
 
| 項目 | 出す条件 | 動き |
|---|---|---|
| 色・絵文字・記念日 | いつも | `showOshiColorSheet(context, oshi)`（札を押したときと同じ。札を押す操作も残す） |
| メンバーを申請する | 承認済みのグループ | `context.push(memberRequestPath(group))` |
| フォローを外す | フォロー中 | `runFollowAction(ref, oshi, follow: false)`（最推しなら最推しも外れる。Fc 3.2） |
 
- ⋮ を出す場所：推しページの「フォロー中の推し」の行と、そこで開いたメンバーの行。推しを探す画面・最推しの箱・シートには出さない。
### 5.4 フォロー中の個人をグループの下に入れる（Fd-5）
 
- 絞り込みが「すべて」のとき：フォロー中の個人のうち、**所属グループのどれかをフォローしている人**は単独の行にしない（そのグループの ▼ の中に出る）。所属グループをフォローしていない個人は今までどおり単独の行。
  - 例：「ステラノート」と「星宮ルナ（ステラノート所属）」をフォロー中なら、行は「ステラノート」だけになり、星宮ルナは ▼ で開いた中に出る。
- そのとき、グループの行の名前の下に「フォロー中のメンバー n人」のチップを出す（n はそのグループのメンバーのうちフォロー中の人数。0人なら出さない）。
- 絞り込みが「個人」のときは、フォロー中の個人をすべて単独の行で出す（グループの行が無いため）。「グループ」のときはグループだけ。
- 絞り込みのチップの件数（すべて・グループ・個人）は、今までどおりフォロー中の数（入れ子にしても変えない）。
### 5.5 メンバーを最初から開いておく（Fd-6）
 
- 推しページのフォロー中の一覧・推しを探す画面とも、グループは最初から開いた状態にする（メンバーを基本表示する）。押すと閉じる。閉じた状態は覚えない。
  - フォロー中の一覧：`_expanded`（開いたグループ）をやめ、`_collapsed`（閉じたグループ）を持つ。
  - 推しを探す：`_expanded[group.key] ?? true`。検索語・ジャンルを変えたら戻す（開いた状態に戻る）。
- 開閉のボタン（`oshi_members_toggle_…`）は、直径 40 の丸（地 `BrandColors.tonal`・墨 2px の枠）に `Icons.expand_less`／`expand_more`（30）。札の下に置く。
### 5.6 推しを探す：まずジャンルを選ぶ（Fd-7）
 
- 画面を開くと、最初に「まずジャンルを選んでください」と、ジャンルのボタン（「すべて」と `OshiGenre` の8つ）を並べる。ボタンは白の地・墨 2px の枠・角丸 12・高さ 76 で、ジャンル名（16・太字）と公開されている推しの数（「n件」）。幅 560 以上は3列、未満は2列。下に「探している推しがいないときは、追加を申請する」。
- 選ぶと、上にジャンルのチップ（「すべて」と8つ。選んだものは墨の地。押すと切り替え）、その下に検索欄（ヒントは「◯◯の中から名前・別名で探す」）、その下に結果。
- 結果は、選んだジャンルの推しだけを `searchOshis` にかけ、`nestOshiResults(結果, 全件)` で入れ子にする。「すべて」は今までどおり全件。
- 名前付きで開いたとき（`?q=`）は、最初から「すべて」を選んだ状態にする。
- 結果が0件の文言：「◯◯の推しはまだいません」「◯◯の中に「…」に合う推しは見つかりませんでした」（「すべて」は今までどおり）。
