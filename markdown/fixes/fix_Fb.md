### 1.1 考え方
 
- グループのフォローは残す（箱推しのため）。グループも個人も「推し」としてフォローできる。
- ただし、**グループには必ずメンバーがいる**ので、メンバーのいないグループは申請できないようにする。
- ファンはふつう個人（推しメン）を選ぶので、個人を先に出す。
## 2. 今の作り（11/7 時点の `dev`、Fb 着手前）
 
- 個人（`oshis`）が所属グループの ID（`groupIds`）を持つだけで、グループ（`groups`）の側にはメンバーの一覧がない。
- この関係は「個人 → グループ」の向きにだけ使われている（個人を選ぶと、ライブを追加する画面・掲示板で、所属グループのライブ・投稿もまとめて出る）。
- 「グループ → メンバー」の向きは何もない。グループをフォローしてもメンバーは出ず、メンバーが1人もいないグループも申請できる。
- 推しの申請画面（`oshi_request_page.dart`）は、種別の選択が「グループ／個人」の順で、初期値がグループ。
- フォロー中の推し（`followingOshisProvider`）は、グループと個人をまぜて名前順に並べている。
- 個人を申請するとき、所属グループには承認済みのグループしか選べない（`FirestoreOshiRepository.request` が確かめる）。
- `firestore.rules` は、個人を作るときに所属グループが存在するかを確かめていない。
## 3. 決定事項
 
### 3.1 個人を先にする（Fb-1）
 
- 推しの申請画面の種別を「個人／グループ」の順にし、初期値を個人にする。
- フォロー中の推し（`followingOshisProvider`）を、個人を先、グループを後に並べる（それぞれ名前順）。
  - 推しの画面のフォロー中の一覧、掲示板の推しの選択（初期選択は先頭なので個人になる）、投稿の対象の推しのチップが、個人から並ぶ。
### 3.2 グループのメンバーを見る（Fb-2・Fb-4）
 
- 推しを探す・フォロー中の一覧で、**グループの行を押すと、メンバーの一覧のシート**を出す（`lib/features/oshi/group_members_sheet.dart`、関数 `showGroupMembersSheet(context, group)`）。
  - シートは `useRootNavigator: true` で開き、外枠（左のタブ）ごと暗くする（Fb-4）。
  - メンバー：`allOshisProvider` のうち、個人で `groupIds` にそのグループの ID を含むもの。承認済みを先（`searchOshis(list, '')`）、申請中を後（名前順）に並べる（Fb-4。申請中のグループはメンバーも申請中なので）。
  - 各メンバーの行は `OshiListTile` を使い、シートの中でそのままフォローできる（申請中のメンバーはフォローできない）。
  - シートの上に、グループ名と「メンバー N人」を出す。メンバーが0人なら「まだメンバーが登録されていません」。
  - グループが承認済みなら、一番下に「メンバーを申請する」（Key：`group_members_request_button`）。押すとシートを閉じて、`/oshi/request?group=<グループの ID>` を開く。
  - 申請中のグループでは「申請中のグループです。承認されるとメンバーを申請できます」と出す。
- `OshiListTile` に、`onTap`（任意。グループの行にだけ渡す）と `groupNames`（任意。個人の所属グループの名前）を足した。
  - 行の左に、個人は `Icons.person`、グループは `Icons.groups` のアイコン。
  - 個人の行に「所属：◯◯」、押せるグループの行に「メンバーを見る ›」のラベルを出す。強調のラベル（申請中・メンバーを見る）は、テーマの色を薄く透かした背景にテーマの色の文字。
  - 補助の関数 `groupNamesById(all)`・`groupNamesOf(oshi, names)` を同じファイルに置いた。
- ルート `/oshi/request` で、クエリ `group` を受け取り、`OshiRequestPage(initialGroupId: …)` に渡す。`initialGroupId` があれば、所属グループに入れておく（種別の初期値は個人）。
### 3.3 グループはメンバーを1人以上入れて申請する（Fb-3）
 
- 申請画面で種別がグループのとき、「メンバー（必須・20人まで）」の欄を出す。最初から1つ出ていて、「メンバーを追加」で増やし、× で消せる（欄は1つは残す）。別名の欄と同じ作り（`_AliasEntry` を使い回す）。
- メンバーが空のままだと「メンバーを1人以上入力してください」と出て、申請できない。
- 申請すると、グループと、入力したメンバー（個人）を**1回のバッチで**作る（メンバーのいないグループが残らない）。
  - メンバーは `status: pending`、ジャンルはグループと同じ、`groupIds` は新しいグループの ID だけ。名前以外の項目は入れない。
  - リポジトリに `requestGroupWithMembers(OshiRequest group, List<String> memberNames, {required String uid})` を足した（`OshiRepository` と `FirestoreOshiRepository`）。グループの検査と重複の確認は `request` と同じ。
  - メンバーの名前の検査は `lib/models/oshi.dart` の `cleanMemberNames`・`validateMemberNames`（定数 `maxRequestMembers = 20`）。空でないこと・50文字以内・同じ申請の中で名前が重ならないことだけを確かめ、既存の推しとの重複は確かめない（同じ名前の別人がいるため）。
  - `firestore.rules` は、申請中のグループを所属に持つ個人の作成を拒否しないので、ルールは変えていない。

## 6. 確認したこと（11/7）
 
- Fb-1：フォロー中の推しが個人 → グループの順に並ぶ。申請画面の初期値が個人。
- Fb-2：個人の行に「所属：◯◯」、グループの行に「メンバーを見る ›」。グループを押すとメンバーのシートが出て、フォローできる。「メンバーを申請する」で所属グループが選ばれた申請画面が開く。
- Fb-3：メンバーが空だと申請できない。メンバー付きで申請すると、グループとメンバーが申請中で作られ、メンバーに所属が付く。
- Fb-4 は確認前（申請中のグループのシートに、申請中のメンバーが出ること）。
