## 3. 各機能の要点（詳しくは各仕様書）

### 3.1 遠征（add_E）

- 今あるもの：ライブ詳細の公演の行に「行き方」「周辺の宿」（Google マップ）、「遠征メモ」（交通手段・交通費・宿・宿代・メモ。`users/{uid}/trips/{performanceId}`）。費用管理に遠征費。
- 足すもの：遠征をまとめて見る画面、時刻と現地メモ、リンクの追加、天気。
- 天気：Weather API（日ごとの予報は最大10日先、時間ごとは最大240時間、履歴は過去24時間）。Essentials の SKU で、月1万回の無料枠。API キーはアプリに書かず、Cloud Functions から呼ぶ。会場の位置は都道府県の代表地点の表。公演の日が10日以内なら予報を出す。過去の天気は後から取れないので、メモリーへの記録は「公演の前後に予報・現在の天気を取ったときに保存する」形にする。

### 3.2 アイコン（add_I）

- 推しの絵文字：`users/{uid}/settings/oshiColors` と同じ形の個人の設定。推しの札（`OshiKindBadge`）の中に出す。
- プロフィールのアイコン：Storage（M-5・G-7 の部品をそのまま使う）。投稿などへの出し方（表示名と同じく複製するか、プロフィールを読むか）は仕様書で決める。

### 3.3 推し（add_O）

- 推し始めた日は個人の設定。最推しの箱に「推して◯日」。
- 記念日（100日ごと・1年ごと）と誕生日（推しのデータに無いので、まずは個人の設定）をホームでお祝いする。

### 3.4 通知（add_S）

- Step6 の仕組み（FCM・`fcmTokens`・`sentNotifications`・15分おきの `sendDeadlineReminders`）に足す。
- 新しいマッチの通知は、投稿の作成・更新のときに動く Cloud Functions（Firestore のトリガー）で、相手の投稿と相互マッチしたら相手に送る。

### 3.5 記録（add_R）

- メモリー（`users/{uid}/memories`）を集計するだけで作れるものから。2列の画面の左下などに置く。

### 3.6 交換（add_T）

- X のポスト文：投稿の詳細・自分の投稿から「X で募集する」→ 譲・求・タグ・受け渡しを並べた本文を作り、`https://x.com/intent/post?text=…` を開く。募集画像はブラウザで描いて保存する。
- グッズ管理：交換の共通データ（グッズ・種類）を使い、持っている・欲しいを登録。そこから投稿の作成画面に譲・求を入れて開く。

### 3.7 そのほか（add_X）

- PWA の案内は、iPhone のときにだけ出す。
