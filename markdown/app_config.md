# おしあし（仮）プロジェクト仕様書
 
> 本ドキュメントは、チームメンバーおよび開発支援に使う LLM が、同じ前提で作業するための仕様書である。
> 「決定事項」と「未決定事項」を明確に分けて記載している。
 
## 0. LLM への指示
 
- 本ドキュメントの「決定事項」は確定した仕様として扱うこと。
- 「9. 未決定事項」に挙げた項目は独自に確定させず、必ず「提案」として提示すること。
- 本仕様にない機能を提案する場合は、提案であることを明示すること。
- コマンドは、Dev Container（Docker コンテナ）内で実行する前提で提示すること。
 
## 1. 概要
 
| 項目 | 内容 |
|---|---|
| アプリ名 | おしあし（仮称） |
| 目的 | 推し活（ライブ参戦、チケット申込、グッズ交換、遠征など）をまとめて管理する |
| 提出先 | DevFest GDGoC Japan Hackathon 2026 |
| 対象ユーザー | ジャンルを問わず推し活をしている人（アイドル、声優、アーティスト、アニメなど） |
| 対応端末 | Flutter Web（PC・スマホのブラウザ）。ネイティブアプリは将来対応 |
 
### 差別化ポイント
 
1. **スクショ読み取り**：告知画像やチケットサイトのスクリーンショットから、Gemini で日程・期限を自動抽出する。
2. **共通データ**：同じ推しのユーザー間で、誰かが登録したライブ情報をサーバー上の共通データとして共有する。他のユーザーは自分で登録しなくても利用できる。
 
## 2. 用語定義
 
| 用語 | 定義 |
|---|---|
| 推し | ユーザーが応援する対象。グループまたは個人単位で登録する |
| ライブ | 推しのライブ・イベント。ツアーのように複数の公演を持つことがある |
| 公演 | ライブの1回分。日時と会場を持つ |
| 受付 | チケットの申込受付。FC先行・一般・アプグレなど、1つのライブに複数存在しうる。それぞれ申込期限と入金期限を持つ |
| アプグレ | アップグレード。チケット当選者が追加料金で良い席に変更する申込。当選者のみが対象の受付 |
| 共通データ | 同じ推しのユーザー全員で共有するデータ（推し・ライブ・公演・受付の情報） |
| 個人データ | ユーザー本人だけが読み書きできるデータ（申込状況、記録、費用など） |
| 譲 / 求 | グッズ交換で使う言葉。譲＝出せるもの、求＝欲しいもの |
| 遠征 | ライブのために遠方へ移動・宿泊すること |
 
## 3. 機能一覧と優先度
 
| 優先度 | 機能 |
|---|---|
| P1（必須） | Google ログイン、推しの登録、予定管理、スクショ読み取り、共通データ |
| P2（次点） | グッズ交換マッチング |
| P3（余力があれば） | 遠征サポート、ライブの記録、費用管理 |
 
## 4. 機能詳細
 
### 4.1 推しの登録（P1）
 
- ユーザーは自分の推しを選んでフォローする。
- 推しが未登録の場合、ユーザーは追加を申請できる。運営が承認すると、全ユーザーに公開される。
- 申請時は既存の推しを検索して候補を表示し、重複登録を防ぐ。
- ハッカソン版では、承認は運営が Firebase コンソールで手動で行う。
 
### 4.2 予定管理（P1）
 
- ライブ・公演・受付（申込期限、入金期限）を記録する。
- ユーザーごとに、各受付の申込状況を個人データとして記録する。状態は「未申込／申込済／当選／落選／入金済」とする。
- アプグレのように対象者が限られる受付は、条件を満たすユーザー（そのライブの当選者・入金済の人）にのみ表示・通知する。
- **Google カレンダー連携**：公演日時・申込期限・入金期限を、ユーザーの Google カレンダーに予定として追加する（Google Calendar API）。Google カレンダー以外は将来対応。
- **リマインド通知**：期限が近づいたら、アプリから通知する（FCM の Web プッシュ）。
 
### 4.3 スクショ読み取り（P1）
 
1. ユーザーが画像（スクリーンショットなど）をアップロードする。
2. Gemini で画像から、推し・ライブ名・公演日時・会場・受付種別・申込期限・入金期限を抽出する。
3. 抽出結果を確認画面に表示し、ユーザーが確認・修正してから保存する。
4. 保存前に、共通データに同じライブ・受付が既に存在するかを照合する（4.4 に従う）。
 
### 4.4 共通データ（P1）
 
- 推し・ライブ・公演・受付の情報は共通データとして保存し、その推しをフォローしている全ユーザーが利用できる。
- 新規登録時（手入力・スクショ読み取りの両方）、既存データがあればそれを使い、新しく作成しない。
- 既存データと内容が異なる場合（日程変更など）は、データを更新し、変更履歴（変更前の値・変更後の値・変更者・日時）を残す。
- 個人の申込状況は共通データに含めず、個人データとして保存する。
 
### 4.5 グッズ交換マッチング（P2）
 
- 目的は、交換・売買を募集している人同士を見つける支援である。メルカリのような取引の場ではない。
- 金銭や物のやり取りは、アプリ外で当人同士が行う。アプリは決済・配送を扱わない。
- ユーザーは「譲」と「求」を登録する。交換だけでなく、売買の募集も登録できる。
- 互いの譲と求が一致するユーザーを、自動で提示する。
- 連絡手段は、X アカウントへのリンクと、アプリ内チャット（可能であれば）とする。
 
### 4.6 遠征サポート（P3）
 
- 公演の会場をもとに、宿泊先と行き方（交通手段）を提示する。
- 遠征の予定（交通・宿）と費用を記録する。
 
### 4.7 ライブの記録（P3）
 
- 参戦したライブを、アルバムのように残す。
- 記録項目は、写真・座席・セトリ・感想を想定する。
 
### 4.8 費用管理（P3）
 
- チケット・グッズ・遠征費の支出を記録する。
- 支出を集計し、予算を管理する。
 
## 5. 非機能要件
 
- 推しの追加は、運営の承認を経て公開する。
- Firestore のセキュリティルールで、個人データは本人のみが読み書きできるようにする。
- 公開前に App Check の導入を検討する。

## 7. 開発環境
 
- Mac 上の Docker（VS Code Dev Container）で開発する。`flutter`・`firebase`・`flutterfire` コマンドはすべてコンテナ内で実行する。
- Firebase プロジェクトは、ハッカソン用の Google アカウントで作成した。チームメンバーは、各自の Google アカウントを Firebase プロジェクトのメンバーとして追加して使う。
- `pubspec.yaml` には、Web のコンパイルエラーを回避するため、`flutter_web_plugins`（`sdk: flutter`）を明示的に追加している。
 
### 起動方法
 
```bash
flutter run -d web-server --web-hostname 0.0.0.0 --web-port 8080
```
 
Mac のブラウザで `http://localhost:8080` を開く。パッケージを追加したときは、ホットリスタートではなく再起動する。
 
### `.devcontainer/Dockerfile`
 
```dockerfile
FROM ubuntu:26.04
 
RUN apt-get update && apt-get install -y bash ca-certificates curl git unzip xz-utils zip libglu1-mesa && rm -rf /var/lib/apt/lists/*
 
# Node.js と Firebase CLI
RUN curl -fsSL https://deb.nodesource.com/setup_22.x | bash - \
    && apt-get install -y nodejs \
    && rm -rf /var/lib/apt/lists/* \
    && npm install -g firebase-tools
 
# Flutter
RUN git clone https://github.com/flutter/flutter.git -b stable /flutter
ENV PATH="/flutter/bin:/root/.pub-cache/bin:${PATH}"
RUN flutter config --enable-web
 
# FlutterFire CLI
RUN dart pub global activate flutterfire_cli
```
 
### `.devcontainer/devcontainer.json`

## 8. 現在の実装状況
 
- Flutter プロジェクト作成済み。FlutterFire CLI で Web アプリのみ Firebase に登録済み（`lib/firebase_options.dart`）。
- Firebase の初期化処理を実装済み。
- Google ログイン／ログアウトを実装済み。
- Firestore の読み書きとリアルタイム表示を、動作確認用のパス `users/{uid}/test` で確認済み。
- セキュリティルールは、`users/{userId}/**` を本人のみ読み書き可能とし、それ以外はすべて拒否している。
- アプリ本体の機能（4章）は未着手。
