## 1. 概要

| 項目 | 内容 |
|---|---|
| 機能名 | メモリー（ライブの記録） |
| 優先度 | P3 |
| 担当 | B |
| 目的 | 参戦する・参戦したライブを、座席・セトリ・感想・写真とともにアルバムのように残す |

### 利用の流れ

1. 当選したら、ライブの詳細画面の公演から「記録する」を押し、参戦予定として記録を作る。座席がわかれば入れておく。
2. 公演日を過ぎると、記録は参戦済みとして表示される。
3. 参戦後に、セトリ・感想・写真を書き足す。
4. メモリーの一覧で、参戦予定と参戦済みのアルバムを見返す。

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| 記録 | 1つの公演についての、ユーザー個人の記録。個人データとして保存する |
| 参戦予定 | 公演日時が現在より後の記録 |
| 参戦済み | 公演日時が現在以前の記録 |
| セトリ | セットリスト。公演で披露された曲名の一覧 |

## 3. 決定事項

### 3.1 記録の単位

- 記録は、共通データの公演1つにつき1件とする。
- 記録する公演は、登録済みのライブの公演から選ぶ。未登録のライブは、先にライブを登録してもらう。
- 記録は個人データとし、本人だけが読み書きできる。

### 3.2 状態

- 状態は保存せず、公演日時と現在時刻から「参戦予定」「参戦済み」を判定して表示する。
- 参戦予定のうちから座席を入れられる。セトリ・感想・写真も、状態にかかわらず入力できる。

### 3.3 記録項目

| 項目 | 内容 |
|---|---|
| 座席 | 文字で入力（例：アリーナ B3ブロック 12列 34番） |
| セトリ | 曲名の一覧。入力欄に1行1曲で書く |
| 感想 | 文章 |
| 写真 | 1記録あたり最大8枚、1枚 5MB 以下。アップロード前に長辺 1600px 程度に縮小する（グッズ交換と同じ） |

### 3.4 記録の作成・編集・削除

- 記録の作成は、ライブの詳細画面の公演ごとの「記録する」から行う。すでに記録がある公演では「記録を見る」とする。
- 編集・削除は、記録の詳細画面から行う。削除は編集画面の AppBar に置き、「記録の詳細 → 編集 → 削除」の順でたどる（M-3 で決定）。

### 3.5 一覧（アルバム）

- ホームの「メモリー」から開く。
- 「参戦予定」（公演日時の近い順）と「参戦済み」（公演日時の新しい順）に分けて表示する。
- 参戦済みは、表紙の写真（1枚目）・ライブ名・日付・会場のカードで並べる。写真がない場合は、写真なしのカードとする。

### 3.6 写真と料金プラン

- 写真は M-5 で実装する。それまでは `images` を空の配列とする。
- 写真は Cloud Storage for Firebase に保存し、グッズ交換の G-7 と同じ縮小・アップロードの仕組みを使う。
- M-5 は、Blaze への切り替え後に G-7 とあわせて行う。

### 3.7 ルート（M-3・M-4 で決定）

| パス | 画面 |
|---|---|
| `/memories` | メモリー一覧 |
| `/memories/:performanceId` | 記録の詳細 |
| `/memories/:performanceId/edit` | 記録の編集 |
| `/lives/:liveId/memory/:performanceId` | 記録の作成（すでに記録があれば編集になる） |

- `/memories` 以下はホームの下に入れ子にし、戻るボタンで一覧・ホームへ戻れるようにする。
- 作成はライブの詳細の下に置く。ライブ名・公演を記録に複製するために `liveId` が要るためである。編集は記録に複製済みの値で足りるため、`performanceId` だけとする。
- 作成と編集は同じ画面（`MemoryFormPage`）を使い、記録の有無で切り替える。

### 3.8 画面の遷移（M-3・M-4 で決定）

- ライブの詳細の「記録する」は作成画面へ `go` で移る。「記録を見る」は記録の詳細へ `push` で移り、戻るとライブの詳細に戻る。
- 「記録する／記録を見る」のボタンは、記録の読み込みが終わるまで出さない（ライブの詳細の表示を遅らせないため）。
- 保存・削除のあとの戻り先は次のとおりとする。

| 操作 | 戻り先 |
|---|---|
| 作成 | ライブの詳細 |
| 編集の保存 | 記録の詳細 |
| 削除 | メモリー一覧 |

### 3.9 一覧・詳細の表示（M-4 で決定）

- 一覧は、1画面に「参戦予定」「参戦済み」の見出しを付けて縦に並べる（タブにはしない）。
- 参戦予定は行（日時・ライブ名・会場・座席）で並べる。参戦済みはカードを、画面幅に応じた列数のグリッドで並べる（カードの最大幅 220px）。
- 写真がないカードは、アイコンを置いた色付きの枠を表紙の代わりにする。
- 記録がないときは、ライブの詳細の公演から記録できることを案内する。
- 詳細画面には、ライブ名・日時・会場・「参戦予定／参戦済み」のラベル・座席・セトリ（番号付き）・感想を表示し、AppBar に「編集」を置く。未入力の項目は「未入力」と表示する。
- 状態の判定には、既存の `nowProvider`（1分ごとに更新）を使う。
- 一覧も1件の取得も、自分の記録すべての購読（`myMemoriesProvider`）1つから作り、読み取りを増やさない。

### 3.10 入力（M-3 で決定）

- 座席・感想は前後の空白を除き、空なら保存しない（編集時はその項目を消す）。
- セトリは1行1曲とし、各行の前後の空白を除き、空行は捨てる。100曲または1曲100文字を超えると保存できない。
- 座席は100文字、感想は2,000文字までしか入力できない。
- 編集では、複製した項目（ライブ名・開演日時・会場）は書き換えない。

## 4. 画面構成

| 画面 | 内容 |
|---|---|
| メモリー一覧 | 参戦予定と参戦済み（アルバム）の一覧 |
| 記録の作成・編集 | 公演（固定表示）、座席、セトリ、感想、写真。編集時は AppBar に削除 |
| 記録の詳細 | 記録の内容と写真。AppBar に編集 |
| ライブの詳細（既存） | 公演ごとに「記録する」「記録を見る」を追加する |
| ホーム（既存） | 「グッズ交換」の下に「メモリー」のボタンを追加する |

## 5. データ構造

```
users/{uid}/memories/{performanceId}   記録（ドキュメント ID は公演 ID）
```

| フィールド | 型 | 必須 | 内容 |
|---|---|---|---|
| liveId | string | ○ | ライブの ID |
| liveTitle | string | ○ | ライブ名（複製。一覧の表示用） |
| startAt | timestamp | ○ | 開演日時（複製。並び順と状態の判定に使う） |
| venue | string | ○ | 会場名（複製） |
| seat | string | | 座席（100文字まで） |
| setlist | array | | 曲名（string の配列。100曲まで、各100文字まで） |
| impression | string | | 感想（2,000文字まで） |
| images | array | ○ | 写真（Storage のパス `users/{uid}/memories/{performanceId}/{ファイル名}` の配列。8枚まで。1枚目が表紙） |
| createdAt | timestamp | ○ | 作成日時 |
| updatedAt | timestamp | ○ | 更新日時 |

- セキュリティルールは、既存の `users/{userId}/{subcollection}/**`（本人のみ読み書き可）で足りるため、変更しない。
- 写真の保存先は `users/{uid}/memories/{performanceId}/{ファイル名}` とし、Storage のルールで本人のみ読み書き可とする（M-5）。

## 9. 未決定事項

以下は未決定である。LLM は独自に確定させず、提案として提示すること。

- 記録を他のユーザーに公開・共有するか
- ライブの名前・会場が変更されたとき、記録の複製した値を更新するか（現在の実装では更新しない）
