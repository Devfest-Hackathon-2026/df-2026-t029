# 判断ログ：架空の公式サイトと Google の架空の推し（2026-11-09）

手書きのメモ（G-Palette・プロフィール・仮のライブ・ほかのグループ・スクショ①）をもとに、Claude（Cowork）と作った。

## 決めたこと

| 決めたこと | 比べた案 | 選んだ理由・捨てた理由 |
|---|---|---|
| 公式サイトはおしあしと別のサイト（`demo_site/`、独自の firebase.json） | おしあし本体の Hosting の下に置く | 本体の公開・ルール・Functions に触れずに作り直せる。「公式サイトはアプリの外にある」という本番に近い形になる |
| 推しだけシードし、ライブはサイトから取得させる | ライブもシードする | 自動取得（Vertex AI）そのものをデモできる |
| 推しの ID を `gdemo-` にする | `demo-` のまま／Functions の `demo-` の除外を外す | `run.js`・`dailyLiveFetch`・承認時の取得が `demo-` を除外している。除外は既存のデモデータを守るためなので、Functions は変えずに ID を分けた |
| 1つのサイトに4つの推しの「公式サイト」をパスで分けて置く | 推しごとにサイトを作る | クローラーは同じオリジンの中だけを辿るので、パスで分けても動く。Hosting のサイトが1つで済む |
| HTML は基準日から生成（`build.mjs --base`） | 日付を書いた静的な HTML | シードと同じく撮影の日に合わせられる。入金期限「今日の 21:00」などの状態を必ず出せる |
| 版A／版B を用意 | Firestore を手で書き換える | 「公式サイトが更新された → 取り直すと照合・変更履歴が出る」という本番と同じ流れでデモできる |
| スクショ用の X 投稿もどきを同じサイトの `/_shot/` に置き、読ませない | 別のサイトに置く／画像で用意する | robots.txt で禁止すればクローラーは開かない（確認済み）。さらにリンクしない・noindex・本文を JS で描くことで、Gemini の URL コンテキストや検索からも見えにくくした。ブラウザで開けば撮れる |
| 投稿もどきには公式サイトに無いライブ（フェス・対バン）だけを書く | 公式サイトと同じライブを書く | 「SNS でしか告知されないライブをスクショで足す」という使い分けが見せられる。同じライブだと自動取得と区別できない |

## 確かめたこと

- `functions/live_fetch/crawl.js` の `collectLivePages` をローカルのサーバーに当て、4つの推しすべてで、これからのライブの詳細ページに届くこと。
- `page_check.js` の `isAllowed` で `/_shot/` が禁止、ライブのページが許可になること。
- `demo_site` の `npm test`（5件）、`tools/seed` の `npm test`（既存4件＋追加4件）。

## AI の使い方

- 手書きメモの読み取りと言語化、既存の Functions（クローラーの語・除外・`demo-` の除外）の読み取りを Claude に任せ、サイトの構成をそれに合わせた。
- 「推しだけシードしてライブはサイトから取る」「投稿もどきは読ませない」は人間が決めた。ID の分け方・隠し方の具体は Claude の案で、人間の確認待ち。
